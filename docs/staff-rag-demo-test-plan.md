# 직원 AI 챗봇 수동 E2E 통합·시연 테스트 계획서

## 1. 문서 목적

- **대규모 QA 품질 평가**(반영민 팀원의 QA 질문셋, `docs/rag-evaluation-question-set.md`)는 수십~수백 건
  질문으로 RAG 답변의 정확도·품질 분포를 통계적으로 측정하는 것이 목적입니다.
- 이 문서는 그것과 다릅니다. **발표·시연 직전에 로그인 → 소속 매장 확인 → 매뉴얼 검색 → RAG 답변**까지
  핵심 흐름이 실제로 동작하는지 소수의 시나리오로 수동 확인하는 **통합 인수 테스트 계획서**입니다.
- 이 문서는 반영민 팀원의 QA 질문셋을 대체하거나 중복 작성하지 않습니다. RAG 품질 자체를 통계적으로
  평가하려면 기존 QA 질문셋과 `npm run eval:rag-dataset`을 사용하세요.
- 인증번호 발급(007), 프로필·지점 등록(008), 프랜차이즈·매뉴얼 검색 범위(010)는 다른 팀원이 작업 중이며
  현재 저장소에 최종 계약이 없습니다. 이 문서는 해당 스키마나 API 계약을 추측하지 않고, 확인되지 않은
  부분은 모두 **TBD**로 표시합니다.
- 실제 RAG 임계값은 **코드 기준(`app/api/rag/query/route.ts`) `answered ≥ 0.60`, `cautious ≥ 0.40`
  이상 `< 0.60`, `insufficient < 0.40`**입니다. 발표 자료나 문서에 다른 임계값이 적혀 있어도 실제 판정은
  코드 기준을 따릅니다.

## 2. 실행 전 준비사항

- [ ] 최신 `develop` 또는 이번 통합 대상 브랜치로 체크아웃했다.
- [ ] `npm install`이 오류 없이 완료됐다.
- [ ] 필요한 환경변수 **이름의 존재 여부만** 확인했다 (값은 이 문서 어디에도 기록하지 않는다).
- [ ] Supabase 마이그레이션이 의도한 순서(001부터 현재 병합된 번호까지)로 적용되어 있는지 확인했다.
- [ ] 시연에 사용할 테스트 계정이 존재하는지 확인했다(계정 값 자체는 별도 보안 채널에서 관리).
- [ ] 시연에 사용할 매뉴얼이 `approved` 상태인지 확인했다.
- [ ] 해당 매뉴얼의 `manual_chunks`와 embedding이 생성되어 있는지 확인했다.
- [ ] 로컬 서버(`npm run dev` 등)를 실행했다.
- [ ] `npm run verify:poc`가 통과했다.

## 3. 결과 상태 정의

| 상태 | 의미 |
|---|---|
| PASS | 기대 결과대로 동작함을 확인했다 |
| FAIL | 기대 결과와 다르게 동작했다 |
| BLOCKED | 선행 조건(다른 팀원 작업, 계약 미확정 등)이 없어서 실행할 수 없다 |
| NOT RUN | 아직 실행하지 않았다 |
| TBD | 기대 결과 또는 계약 자체가 아직 확정되지 않았다 |

## 4. 테스트 결과 기록 표

모든 시나리오는 아래 표 형식으로 기록합니다.

| ID | 영역 | 사전 조건 | 실행 절차 | 기대 결과 | 실제 결과 | 상태 | 증거 | 비고 |
|---|---|---|---|---|---|---|---|---|
| 예시 | 인증 | ... | ... | ... | ... | NOT RUN | ... | ... |

증거 칸에는 **스크린샷 파일명, HTTP status 코드, 비식별 로그 요약**만 기록합니다. 비밀번호, 인증번호,
UUID, Cookie, Authorization 헤더, API 키, 토큰은 증거로 남기지 않습니다.

### RAG 응답 (RAG)

| ID | 영역 | 사전 조건 | 실행 절차 | 기대 결과 | 실제 결과 | 상태 | 증거 | 비고 |
|---|---|---|---|---|---|---|---|---|
| RAG-01 | RAG | 이수점 평일 영업시간 관련 approved 매뉴얼과 embedding 존재 | "이수점 평일 영업시간에 대해서 알려줘" 질문 | `status`가 `answered` 또는 `cautious`, 올바른 source 반환 | | NOT RUN | | |
| RAG-02 | RAG | 본사 공통 매뉴얼 approved 및 indexing 완료 | 같은 프랜차이즈 소속 지점에서 공통 매뉴얼 질문 | 해당 지점에서 공통 매뉴얼 근거로 검색됨 | | NOT RUN | | |
| RAG-03 | RAG | 본인 지점 전용 매뉴얼 approved 및 indexing 완료 | 본인 지점 전용 매뉴얼 질문 | 본인 지점에서만 검색됨 | | NOT RUN | | |

| RAG-05 | RAG | 다른 프랜차이즈 매뉴얼 존재 | 다른 브랜드 관련 질문 | 다른 브랜드 매뉴얼이 source/matches/answer 어디에도 나타나지 않음 | | NOT RUN | | 010 계약 확인 후 재검증 |

## 6. RAG 응답 확인 항목

각 RAG 시나리오 실행 시 아래 항목을 확인하고 기록합니다. **실제 UUID는 이 문서에 기록하지 않습니다.**

- [ ] HTTP status
- [ ] `answer` 존재 여부
- [ ] `status` (`answered` / `cautious` / `insufficient`)
- [ ] similarity 값(코드 기준 0.60/0.40과 비교)
- [ ] source 존재 여부, 제목/카테고리(원문 대신 존재 유무와 일반 분류만 기록)
- [ ] `matches` 개수
- [ ] 다른 매장·다른 브랜드 정보가 포함되어 있는지 여부

## 7. 장애 원인 분류표

| 코드 | 의미 | 확인 위치 | 담당 영역 |
|---|---|---|---|
| ACCOUNT_LINK | 로그인/계정과 profile 연결 문제 | 인증 코드, 세션/profile 조회 | 인증 |
| STORE_MEMBERSHIP | 매장 소속·승인 상태 문제 | `store_memberships`, 승인 흐름 | DB/인증 |
| MANUAL_MISSING | 대상 매뉴얼 자체가 없음 | 매뉴얼 목록, DB | 매뉴얼 |
| MANUAL_NOT_APPROVED | 매뉴얼이 draft 등 미승인 상태 | 매뉴얼 상태 컬럼 | 매뉴얼 |
| CHUNK_MISSING | `manual_chunks` 미생성 | 인덱싱 결과, chunkCount | 매뉴얼 |
| EMBEDDING_MISSING | chunk는 있으나 embedding 누락 | 인덱싱 로그, DB | 매뉴얼 |
| RPC_CONTRACT | 검색 RPC 요청/응답 계약 불일치 | 005 마이그레이션, RPC 정의 | DB/RAG |
| STORE_SCOPE | 매장 범위 필터링 오류(타 지점 노출 등) | 검색 쿼리의 `store_id` 조건 | RAG/DB |
| FRANCHISE_SCOPE | 프랜차이즈 범위 필터링 오류(타 브랜드 노출 등) | 010 관련 검색 범위 로직 | RAG/DB |
| THRESHOLD | 임계값 판정 문제(0.60/0.40) | `app/api/rag/query/route.ts` | RAG |
| EXTERNAL_API | OpenAI/Supabase 등 외부 API 실패 | API 응답, 서버 로그 | RAG |
| LOGGING | 질문 로그 저장/미저장 문제 | `save-question-log` 연결 여부 | RAG/DB |
| UNKNOWN | 위 분류로 설명되지 않는 문제 | 추가 조사 필요 | 통합 담당 |

## 8. 시연용 최소 통과 기준

시연 진행 여부를 판단하는 최소 기준입니다. 아래 항목이 모두 PASS여야 시연을 진행합니다.

- [ ] 로그인 성공
- [ ] 올바른 매장이 화면에 표시됨
- [ ] 본사 공통 매뉴얼 기반 답변 1건 성공
- [ ] 지점 전용 매뉴얼 기반 답변 1건 성공
- [ ] 다른 지점·다른 브랜드 데이터 격리 확인
- [ ] `insufficient` 응답 1건 확인
- [ ] source 표시 확인
- [ ] 비밀값(서비스 키, 토큰, Authorization 등) 미노출 확인
- [ ] `npm run verify:poc` PASS
