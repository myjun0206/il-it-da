## Server-Owned Minimal Collection

Development server callbacks write an ignored local execution ledger under the same trace, independently of browser interception:

- Embedding and generation HTTP status, input/output tokens, verified/missing-usage flag, and Standard-rate estimate when usage is valid.
- Verified numeric bounds/quantity/unit/approximation, serving/mode, hashed menu/ingredient/basis identifiers, manual/chunk identifiers, source offsets, original-span and citation hashes.
- Source-rendered answer hash and final-output hash/status/score. Source-rendering occurs before the unchanged cautious notice, so those hashes intentionally differ when a notice is appended.

No full AI answer, raw prompt, source quote/text, source title, personal account fields, API key, or readiness proof is written to this new ledger. Missing usage is unknown, never zero or a verified cost. Existing minimum numeric diagnostics remain separate from source-derived final output. Diagnostics are development-only, local, ignored, and not public/persistent support metadata.

Ordinary responses tolerate diagnostic failures. Explicit E2E marks capture failure and cannot pass verification; readiness checks files before issuing proof. Source rendering still refuses wrong values/units/menu/HOT/ICE, missing compound facts, conflicts, invalid citations, and unsupported scope; only the existing independently verified qualifier-only path remains allowed.
